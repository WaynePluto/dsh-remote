# 会话滚动导航（chat-scroll）开发方案

状态：已按方案实现并完成自动测试、构建产物检查与隔离 dsh 浏览器验证；待用户实机确认两种动效后再勾选 roadmap。

## 1. 目标与边界

将 `packages/plugins/agent-message-start` 扩展并更名为 `packages/plugins/chat-scroll`，
包名为 `@dsh-remote/dsh-plugin-chat-scroll`，中文功能名称为「会话滚动导航」。
仍是一个内置插件，不并行装载新旧两份实现。

用户已明确要求两个显式导航动作都有滚动动效：

| 动作 | 目标行为 |
|---|---|
| 回到消息开头 | 平滑移动到这条消息的 24px 阅读线，确认到达后闪烁分界线 |
| 原生返回底部下箭头 | 平滑回到真实底部，随后恢复 dsh 的新消息自动跟随 |

保留历史会话首次点击修复、每个按钮只定位自己消息、短消息尾部空间补偿。
系统开启「减少动态效果」时瞬时定位；已在目标附近时不强行动画。

本次不增加按钮、不重做按钮外观、不增加设置页、数据库、RPC 或运行时依赖。
不改变流式输出跟随、历史分页、原生 Turn 导航和会话位置恢复的默认动效。
不修改/fork dsh，不复制 ChatView，不读取 React 私有状态，不劫持全局滚动 API，
不对会话容器全局设置 `scroll-behavior: smooth`，不移动或替换 React 拥有的节点。

基线：dsh `0.1.6-alpha.2` / `ddefc45fbc`。以下路径均相对于上游根目录。

结论：不存在可以直接注册的「返回底部动画」API。已在真实隔离 dsh 页面验证本方案：消息开头采样存在多个中间位置，底部按钮采样存在多个中间位置并最终由原生 click 回到底部；失败/多匹配路径仍以自动测试覆盖。

## 3. 统一导航控制器

### 3.1 作用域与互斥

每个会话视图/实际滚动容器只保留一个活动导航任务，以 sessionId、flow 和任务代号核对身份。
消息按钮与底部按钮请求同一个控制器，不再各自持有彼此独立的动画。
新导航取代旧导航；旧任务的帧、落点回调和分界线不能影响新任务。

通过 `conversation.input.dock` 的会话级组件安装局部事件监听并持有生命周期。
在点击时解析实际 flow/scrollport；不为每条消息重复注册底部监听，不持续全量扫描页面。
根节点更换、会话切换、视图切换、插件卸载后取消任务并释放资源。

状态划分：等待目标 → 准备几何 → 动画 → 落点确认/原生交接 → 完成。
任何阶段均可以取消；超时与缺失目标不能显示成功分界线。

### 3.2 双向共用动画

采用 `requestAnimationFrame` 驱动的短时缓出动画，而不是完全依赖浏览器一次性的 smooth 请求。
每帧以无内建动画的滚动写入推进小段距离，连续帧组成平滑动效；不向最终目标直接大幅跳跃。
这样可以观察实际进展，并处理原生跟随取消动画的既有问题。

建议初始时长按距离限制在约 200–450ms，长距离也不播放数秒动画；最终数值通过原型测量调整。
按帧重新测量目标和真实位置，布局变化时从实际位置调整后续路径，不无限重启动画计时。
消息目标等待沿用最多 3 秒，动画与有限校正总预算沿用最多 1.8 秒。

正常情况下不得把「160ms 后大跳到终点」作为动效实现；瞬时定位仅用于减少动态效果、
无需明显移动的近距离动作或异常降级。原生持续抢占的恢复策略必须在原型中验证。

中断规则：

- 滚轮、触摸拖动、滚动条操作和滚动导航键优先于程序动画。
- 捕获这次导航 click 之后才建立任务，避免触发按钮本身的输入立即取消新任务。
- 不吞用户的键盘、触摸和滚轮事件；普通输入框打字不应被当作滚动导航键。
- 切换会话/视图、发起新导航、卸载或页面进入后台时取消，不在后台恢复后继续拉动页面。
- 用户取消后不再校正、不重放原生 click、不显示完成分界线。

### 3.3 回到消息开头

保留 `messageId → Chat snapshot → data-chat-flow-key` 定位链和 24px 阅读线。
先等待正确消息行，再计算实际 scrollport 与所需尾部留白，最后启动统一动画。
目标在同一 DOM 节点内发生位置变化也要复测；不得靠「加载更早」使首击生效。
落点在容差内稳定后才显示原有分界线，不提前宣布成功。

### 3.4 返回底部与原生状态交接

保留 dsh 原生按钮，使用局部捕获阶段监听它的 click，兼容鼠标、触摸生成的 click 和键盘激活。
定位必须同时核对会话边界、Chat flow 邻接结构、按钮角色和当前 chat locale 的文案。
不能只匹配中文提示、所有向下箭头或某一个编译后的 CSS hash。

候选过程：

1. 确认唯一原生按钮和实际滚动容器、没有无法安全接管的导航状态；不满足则原样放行。
2. 取消旧消息定位并清理分界线，协调已有尾部留白，重新计算自然底部。
3. 仅在接管成立时阻止本次原生立即跳转，启动插件动画。
4. 跟踪流式内容增长后的最新底部，采用有总时限的目标更新，不追逐终点到无穷。
5. 在原生按钮尚连接、会话/flow 身份仍相同的同步阶段，把最终归位交给该按钮的原生 click。
   使用任务局部、try/finally 保护的重放标记避免递归捕获，只执行一次。
6. 由原生 toBottom 清理 pending jump/分页锚点、恢复跟随和阅读位置状态；插件随后退出控制。

**交接难点：** 接近底部会导致按钮卸载，不能先等动画完全结束或 scrollend，再点击旧 DOM。
原型需比较同步最终帧交接与保留小段阈值外距离再交接的方案；需要消除可见的末端跳变，
并测试滚动采样、内容增长/缩短、按钮重渲染与待完成 Turn 跳转，不能依赖「动画小于 500ms」赌时序。

若动画中按钮提前消失，先判断是否已经由原生进入正常底部状态；禁止点击已脱离 DOM 的旧按钮。
若不能证明安全交接，应停止增强或在仍有效时交还原生行为，发出一次诊断；不要伪造内部状态。
这项原型不通过，就暂停底部动效开发并重新对齐方案，不升级成全局 API hook 或复制 ChatView。

### 3.5 尾部留白

将现有全局 activeCushion 改为控制器拥有的临时资源。
消息开头定位按需增加，切换导航时协调，用户输入/卸载时恢复原样。
返回底部的目标必须排除这部分插件留白。要区分导航按钮的 pointerdown/键盘激活与普通读者输入，
不能沿用「所有 pointerdown 先删留白」而在 click 到达前就发生跳动；导航接管成功后统一收回。
尤其要验证短回复：直接删除留白可能触发浏览器 clamp；若会产生明显跳变，需随动画平滑收回，
最终原生交接前归零。不能先瞬移删空间再播放一小段动画冒充全程平滑。

## 4. 建议文件划分

所有路径位于 `packages/plugins/chat-scroll/`，具体文件数量可按实现复杂度合并。

| 文件 | 职责 |
|---|---|
| `src/client/index.tsx` | 文案、样式、消息动作与会话控制组件注册/卸载 |
| `src/client/AgentMessageStartButton.tsx` | 消息按钮与分界线表现，只提交导航请求 |
| `src/client/ScrollNavigationMount.tsx` | 会话级生命周期、根节点绑定与取消 |
| `src/client/controller.ts` | 单一任务所有权、上下两种导航、超时及交接 |
| `src/client/animation.ts` | 可测试的帧推进、缓动、动态目标与中断 |
| `src/client/native-bottom.ts` | 原生按钮识别、定向 click 捕获、一次性重放与降级 |
| `src/client/locate.ts` | 现有消息映射和几何计算 |
| `src/client/cushion.ts` | 临时留白的所有权、收回与恢复 |
| `src/client/styles.ts` | 沿用原按钮与分界线外观，不修改原生底部按钮样式 |

只抽取插件确实共用的逻辑，不引入通用动画框架或第二套 dsh 滚动状态机。

## 6. 验收标准

### 自动测试

- 动画有多个中间位置、方向正确、距离不同时长有界；不能只断言最终 scrollTop。
- 原生跟随打断、目标延迟提交、同节点重排、ResizeObserver 和滚动范围变化可控。
- 首次打开分页历史，未经任何预滚动或「加载更早」，向上导航仍成功且有动效。
- 每个消息按钮只定位自身；短回复补空间后往返无残留空白或明显收缩跳变。
- 上下动作互相取代、连续点击不叠加；旧会话即使 flow key 相同也不能完成新会话的动作。
- 原生 click 只重放一次、不可递归；无匹配/多匹配/已卸载按钮不能错误拦截或点击。
- 用户中断后无补跳；取消/失败不闪线，所有帧、监听、观察器及临时样式可释放。
- 减少动态效果无滚动动画；卸载插件后原生按钮功能恢复。

### 真实浏览器与实机

- 深浅主题、中英文、鼠标/键盘/触摸，窗口改变及移动端 composer 高度变化。
- 静态长会话、短回复、历史分页、流式输出、持续工具输出、过程折叠/展开。
- 返回底部后继续收到新内容能正常跟随；手动上滚后不被重新拉回。
- 动画期间切换会话/视图、点击原生 Turn 导航或发送消息时不和原生动作竞争。
- 核查 pending jump/分页补偿的交接，不遗留返回底部后的意外回跳。
- 用位置采样证明两种按钮确实有动效；用浏览器视觉检查证明没有明显末端跳变。

运行包 test/typecheck/build、launcher 测试及全仓 `check:dependencies`、lint、typecheck、build、test；
检查 launcher/dev-stack/pack 的双端产物与唯一装载。构建后必须重启 dsh，不以刷新代替。
浏览器自动化通过不等于用户实机验收，roadmap 两者分别记录。
